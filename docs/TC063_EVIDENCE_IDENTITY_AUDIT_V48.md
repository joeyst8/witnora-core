## Finding 1: TC-063 is a family-level claim, not an archived singular formula

`theory/TC063_BOUNDED_SEPARATOR_AFFINE_HARDENED_THEOREM.md` defines TC-063 as a restricted claim for every formula in `SAF(c,r)`, with fixed separator bound `c`, supported exact-affine bound `r`, and eight explicit proof obligations. Its recorded status is `RESTRICTED_THEOREM_WITH_PROOF_OBLIGATIONS`. There is no single canonical `TC-063.cnf` whose UNSAT proof alone would discharge this quantified theorem.

The examined tracked directories `theory/`, `reproducibility/`, `research/`, `examples/`, `scripts/`, and `docs/` do not advertise a named, paired `TC-063` DIMACS source and G14/G5 JSON certificate bundle. This is an **inventory observation**, not a proof that no relevant data exist in GitHub releases, Actions artifacts, external storage, or unexamined paths. The reproducibility manifest instead identifies an older v0.9.8 Tseitin diagnostic archive; it is **not** an attested TC-063 G14/G5 bundle.

## Finding 2: concrete input proof path exists, but its inputs are instance-scoped

`witnora_core/lean_g14_gate.py` has a source-backed path: verify formula-hash binding; rerun native G14; reconstruct every separator branch, conditioning and component partition; check residual G5 certificates; compare signed source, tokens and raw/canonical clauses; and emit one Lean instance of `G14ConcreteBridge.checked_ascii_dimacs_g14_canonical_unsat`. Only a successful combined kernel run with source text can yield `LEAN_END_TO_END_G14_UNSAT_VERIFIED`.

The combined proof checks **UNSAT for that particular accepted ASCII DIMACS source**. It does not establish (i) recognition and complete certificate production for every member of `SAF(c,r)`, (ii) polynomial-time generation/checking with a justified finite machine-cost model, or (iii) universal CPython implementation refinement.

The v47 2/3/4-component cases are **synthetically constructed test instances**. Their source SHA-256 values in generator output identify those generated bytes only; none is a remotely designated or independent TC-063 source artifact.

## Concrete source/certificate intake contract

For a future independent target, require all of the following **before** calling it source-bound:

| Input | Required evidence | Reject if |
|---|---|---|
| Original DIMACS | Exact ASCII source bytes, origin/commit or release, SHA-256 | No original bytes, unsupported syntax, or unknown provenance |
| Canonical formula | Raw signed clauses, token/lexeme record, canonical clauses, `formula_hash` | Lean document/token/canonical check fails |
| G14 certificate | Exact JSON payload, separator IDs, exhaustive branch IDs and assignments | Missing/duplicate branch, wrong source hash, inconsistent residual partition |
| G5 per branch | Chosen component, initial affine rows, indexed XOR steps | Missing branch witness, wrong selected component, native or Lean G5 rejection |
| Combined attestation | Reproducible Lean toolchain/run result, complete proof-source hash, source+certificate input hash | Only native `UNSAT_CERTIFIED`, separate partial checks, timeout, or failure |

Use the existing command (with its pinned Lean project) on such an independently selected pair:

```bash
python -m witnora_core.separator_affine_family_theorem check \
  --cnf original.cnf --certificate g14_certificate.json --lean
```

Inspect `lean_formal_status`, `source_document_verified`, `input_sha256`, `complete_proof_source_sha256`, and branch checks. The certificate's own claimed formal status is not trusted. A hash identifies bytes; it is not an authenticated signature.

## The correct next theorem-level target

1. State `SAF(c,r)` membership as executable mathematical predicates over source CNFs, separator evidence and exact affine component evidence. Make any partial recognizer's failure semantics explicit.
2. Prove universal **soundness**: whenever the accepted decomposition / G5 checker premises hold, the reported SAT witness or UNSAT cover is correct. Concrete G14 UNSAT soundness is already far along; retain an explicit gap list for implementation refinement.
3. Separate **relative completeness** from soundness: for each supported `SAF(c,r)` member, show the algorithm produces a checkable result, *conditional on* justified recognition and affine extraction completeness. A finite sample does not establish this.
4. Formalize the fixed-`c`, fixed-`r` cost model, including separator discovery, certificate length, bit complexity and Lean checker limits. A claim of general polynomial SAT does not follow.
5. If an independently sourced DIMACS/G14/G5 pair is nominated, run the intake contract and report the **first failing premise** verbatim. Until then, `TC-063 target instance proof` is **NOT_RUN / NO_DESIGNATED_ARTIFACT**, not PASS or FAIL.
